## 二、创新数字内容消费 —— 低成本文旅内容量产（S2）

**政策原文锚点**：十五五规划关于「创新数字内容消费」的表述。

**系统实现**（`MultimodalContentService` + `/admin/guide-content` 量产工作台）：

- **一次配置，批量产出**：县域（26 实体）× 模态（图文/语音讲解/宣传画面/视频脚本）×
  风格（清新/活泼/文艺）× 口音（普通话/方言）＝ 一次最多 26×4×3×2＝624 种组合，
  已存在组合自动跳过，可放心重跑。
- **实测内容结构**：图文文案 156 · 语音讲解 156 · 宣传画面 52 · 视频脚本 156，共 520 条；
  模态覆盖 4/4，实体覆盖率 100%（每个实体至少拥有一条内容）。
- **方言版本 260 条**：覆盖全部实体的普通话+方言双版本，支持县域在地文化表达。
- **大模型双轨**：配置 Key 走大模型原创，未配置自动降级本地模板引擎（`useAi` 开关），
  生产不因外部服务中断而停摆——这是「低成本量产」可落地的前提。
- **真实配图**：26/26 实体封面图（14 张真实照片采集 + 12 张 AI 生成宣传画面），
  全部落盘 `frontend/public/images/guide/`，断网可展示。

**与推荐系统的融合点**：内容完备度 g_i 直接进入 式(1) 的评分项 δ·g_i，
内容越全的点位在路线规划中自然获得曝光——内容生产与流量分配形成同一套账。

## 三、智慧文旅发展 —— 千人千面智能导览（S3–S5）

**政策原文锚点**：十五五规划关于「智慧文旅发展」的表述。

**系统实现**（`RouteService` / `GuideService` / `/guide/plan` / `/guide/live`）：

- **画像驱动路线（S3）**：同行人、年龄段、深度、时间预算、节奏、口音、兴趣标签、避堵开关
  8 组输入 → 式(1) `s = 0.40·p + 0.25·h − 0.20·c + 0.15·g` 逐点打分 →
  式(2) `Σw + Σt ≤ T_u`（τ=0.75）在时间预算内装配路线。
- **实测路线**（2026-09-04，深度用户 `test`、4 小时预算、避堵）：
  慢游 **7 站 · 239/240 分钟** · 路线总分 4.444。每个站点给出
  偏好/热度/拥挤/内容四项分数拆解与中文理由，评分过程对游客可见、可解释。
  逐点核算示例——云溪书院 `s = 0.40×1.00 + 0.25×0.70 − 0.20×0.35 + 0.15×1.00 = 0.655`，
  与接口返回值完全一致，式(1) 不是摆设。
- **实时触发导览（S5）**：靠近点位自动触发；讲解深度由
  式(3) `d = ⌊0.30·k_u + 0.25·r_u + 0.20·q_u + 1⌋`（上限 3）实时计算——
  停留越久、提问越多、同行构成越深度，讲解档位自动升级，可点「同步停留，重算档位」立即生效。
- **追问与播报**：预置四类追问（玩多久/典故/附近/亲子），普通话/方言播报走浏览器
  Web Speech API，零 TTS 成本。
- **千人千面的验证**：未填画像的游客档位为 2（k=2,q=2 封顶），
  种子深度用户 `test` 可到档位 3——深度是个性化计算的结果，不是写死的开关。

## 四、乡村振兴数智赋能 —— 轻量化可复制 + 全链路数字化闭环（S1/S6）

**政策原文锚点**：十五五规划关于「乡村振兴数智赋能」的表述。

### 4.1 轻量化可复制

- **零外部强依赖**：JDK17 / Maven / MySQL 8.0 全部免安装便携化（`tools/`），
  未配置任何大模型 Key 也能完整运行全部功能。
- **县域模板化**：知识图谱以「1 县域 + N 实体 + M 关系边」的结构播种
  （当前演示县：梅城古镇，26 实体 = 12 景点 + 6 非遗 + 8 美食，90 条关系边，
  与实施例口径一致）；换一个县，替换种子数据即可复制整套系统。
- **一键启动**：`启动全部.bat` 三个窗口依次拉起数据库/后端/前端，县域运营方无需要求专职运维。
- **3D 素材独立存放**：非遗竹编灯笼 glb 模型放 `assets3d/`（不进前端构建产物），
  56MB 级素材不拖累轻量化交付。

### 4.2 全链路数字化闭环（S6）

**式(4) `h_i^(t+1) = (1−η)·h_i^(t) + η·f_i^(t)`，η = 0.20**（`FeedbackService`）：

- 游客在导览页打分 → 内容质量分 EMA 与实体热度 EMA **同步更新**，端到端实测（2026-09-04）：
  - 云溪书院热度 0.700 → 0.760（f=1.0），代入 0.80×0.700 + 0.2×1.0 = 0.760；
  - 云溪米酒 0.720 → 0.776、梅城古镇城门 0.900 → 0.920；
  - 三条内容的质量分各由 0.000 → 0.200（首次反馈）。
  - 这些数字的复现方式：跑 `python tools/demo_walkthrough.py`（登录 → 规划 → 触发 → 打分一条龙）。
- 更新后的 h_i 回到 式(1) 的 β·h_i 项 → 下一轮路线规划自动偏向游客真正认可的点位；
- 指数平滑保证「一次差评不会把热度打下去，但会让它往下走」，抗单次极端值。
- 看板的 式(4) 演示样本表展示头部实体的 before → f → after 全过程。

**闭环的意义**：S1 建图 → S2 产内容 → S3 排路线 → S4 触发导览 → S5 深度自适应 →
S6 反馈回写 → 回到 S1 的热度与内容完备度——六个步骤在数据库层面是同一张网，
不存在「导览归导览、数据归数据」的两张皮。
